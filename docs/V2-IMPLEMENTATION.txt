Consumer installation, API and security model: docs/extension.md

IMPLEMENTED

Standalone Chrome/Brave extension with no Vercel host, daemon or remote signer.
Abyss Inter/JetBrains Mono typography, Phosphor icons, rounded controls, dark/light
themes and a visible early-alpha label. Pearl accounts only; Midnight stays
in its existing wallet.

Guided creation with 12 words by default or 24 by choice, hidden backup and three
random-word verification before saving. Numbered masked import, paste/checksum
validation, official/web address previews and optional public activity lookup.
Password recovery verifies every existing account and preserves signed records,
revoking site grants and cancelling unsigned reviews.

Encrypted vault, official Oyster/XMSS address derivation,
explicit previous-web-wallet import format, receive/change discovery, canonical
prevout verification, confirmed/pending/immature/reserved/spendable balances,
receive QR, reviewed payments, durable signed journal and exact-byte rebroadcast.

Manual and idle lock, restart lock, password reauthentication for phrase export
and password changes, account selection/labels, additional accounts, custom
Blockbook endpoints verified against network genesis, theme and site revocation.

General window.abyssWallet provider: connect, account/balance reads, reviewed
sendTransaction/signTransaction, disconnect and capabilities. Any approved secure
top-level site can use it. Internal wallet commands are unavailable to sites.
Disconnecting a site cancels unapproved requests but retains signed transactions.

Shared per-provider read pacing and 429 cooldown, respecting Retry-After even
for forced refresh, reduce provider load. Empty histories avoid redundant UTXO
lookups; canonical input verification remains.

Abyss-derived Base UI/shadcn Button/Input controls use an extension-scoped
Tailwind compiler. Readable type, three-column words, manual copy/paste and a
content-sized desktop workspace replace the prior compact-only treatment.
Creation follows backup, verification, then the local password. Version remains
0.1.0 until an actual release.

One serialized owner in ordinary typed modules: state, payments, network, sites,
crypto host/worker and UI. No plugin framework or per-dApp signing implementation.
Keys/signing live in the dedicated worker; authenticated setup/recovery requests
are transiently relayed through the background. Only encrypted recovery data is
persisted. Public account metadata, balances and transaction records are local.

VERIFICATION

The existing suite plus wallet ownership/import tests passes 1679 tests; six
pre-existing live checks remain skipped. Type checking and both extension and
existing testnet web builds pass. Disposable Chrome/Brave profiles cover creation,
encrypted storage, canonical balance reads, connection approval, internal-method
refusal, reviewed signing, uncertain broadcast reservation, exact-byte rebroadcast,
locking, wrong-password rejection, recovery reauthentication, revocation and
browser restart and phrase-based password recovery preserving the signed journal.
Both supported formats restore to native/reference addresses; wrong recovery
phrases leave the vault untouched. Popup setup continues in a normal tab. Public
testnet2 discovery for a fresh unfunded account passed in Brave. The official Go
script engine accepted the extension payment fixture and rejected tampering.
Synthetic signing does not prove live mempool acceptance.

Official Pearl source: 99b95ac5e77450f4deebcc23ec2d30f86a885c26.
64 native account/address fixtures, four XMSS commitments and native script-engine
verification remain available in check:core:reference. native/NOTICE and
native/xmss/provenance.json preserve upstream hashes, licenses and build provenance.
Stateful XMSS script-path signing is not enabled. Key-path payments include the
official XMSS Taproot commitment.

Build/test: npm run build:extension, npm run check:extension, and
VITE_PEARL_NETWORK=mainnet npm test. The extension browser check uses an isolated
profile and controlled observation fixture. Add --live to the browser script for
public testnet2 discovery. tools/check-wallet-setup.mjs checks onboarding and
restoration. Set PEARL_BROWSER_EXECUTABLE to a standalone Brave executable if needed.
For official native signature verification, set PEARL_SOURCE to the pinned Pearl
checkout, PEARL_GO to its required Go executable, then add --native when invoking
tools/check-wallet-extension.mjs. Build its XMSS library with make -C xmss lib.

REMAINING

Abyss swap-screen transport integration and fundSwap/claimSwap/refundSwap support
in the extension, live extension swap/refund acceptance, arbitrary PSBT or message
signing, hardware/watch-only/multisig, contacts/coin-control and independent security
review. Extra BIP-39 passphrases and hexadecimal seed imports are unsupported.
The mainnet configuration exists; live mainnet payments are not validated
for this testnet milestone. Do not describe the alpha as audited or fully complete.
